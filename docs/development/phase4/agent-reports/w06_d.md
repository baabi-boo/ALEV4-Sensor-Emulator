## Confirmed defect

An independent post-optics fixture with provenance `values` containing
100,000 copies of `-pi` occupied 27,105 manifest bytes and 803,354 payload
bytes. Before this fix Python accepted `spatial_arithmetic_checked=True`.
Preserved native `encodeBundleJson` prints each value as
`-3.1415926535897931`: its plain JSON occupies **2,000,012 bytes**.
Actual GNU Octave 9.4.0 rejected it with `ALEV4:InvalidDualGainMetadata`,
`Manifest exceeds the JSON text size bound.` No large allocation was needed.

## Change and independent controls

- Extended the existing typed provenance helper with an incremental byte
  counter. It retains the inherited vocabulary and supported empty shapes.
- Counts 17-significant-digit binary64 tokens, scalar/vector/matrix syntax,
  object punctuation, short/control escapes and unescaped UTF-8 accurately;
  never constructs the complete plain JSON text and stops above 2,000,000.
- Portable keys, 256 fields and nesting are already checked more strictly
  by the typed reader (depth 24 versus legacy JSON depth 64); no duplicate
  validation or smaller arbitrary bound was introduced.
- Added six tests: actual moderate counterexample; real exact-size bundles;
  tiny scalar/vector/matrix/empty counts; literal IEEE edge tokens; measured
  Unicode/control escape counts; and guarded iteration proving early exit.
- Clarified the separately applicable plain-JSON limit in the artifact guide.
