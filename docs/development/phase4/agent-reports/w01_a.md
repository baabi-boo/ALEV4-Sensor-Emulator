## Scope conclusion

The next phase is **Phase 4: sensor noise and readout realism**, encompassing
all five planned slices:

1. **4A:** separate versioned configuration, persistent full-grid maps, explicit
   component order, independent frame identity, disabled-model identity, strict
   validation and caller-state isolation.
2. **4B:** achromatic response multipliers, exposure-dependent dark charge,
   independent photo/dark noise switches, shared total sampled charge and one
   physical full well before gain paths branch.
3. **4C:** signed fixed offsets and row/column electronic components, with
   explicit common versus path-specific placement after the well and before
   gain/black offset/ADC.
4. **4D:** documented temporal behavior, fixed versus temporal distinction,
   exposure sweeps and explicit EI semantics, including clipped/invalid results.
5. **4E:** a new opt-in artifact identity, demonstrations, independent semantic
   verification, failure-path checks, repeat evidence and clean-source release.

Full completion cannot be inferred from implementing only a constructor or
showing visually plausible structured noise.

## Recommended bounded design

- Keep the existing constructors and default APIs unchanged. A new wrapper
  should delegate directly to the existing exposure API when disabled, rather
  than reproduce its RNG draw order. Apply the same rule to spatial wrappers.
- Accept explicit persistent full-grid PRNU, dark-rate and electronic offset
  maps, then slice their active ROI using existing geometry. Use a sensor
  realization identity separate from frame seeds. The plan does not require a
  random-map generator in this initial implementation.
- Define PRNU as a nonnegative achromatic response multiplier with nominal
  unity; do not silently normalize supplied maps. Keep dark-current rate in
  electrons/pixel/second distinct from signed readout offsets in electrons.
- Reuse existing spectral integration exactly once. Draw photo and dark charge
  separately under declared policies; sum before the shared full-well clamp.
  Both paths consume the identical stored array. Reuse observed-channel merge
  without correcting it using hidden noiseless charge or component truth.
- Use explicitly named common/high/low (or common/single) electronics and
  component-specific seeded streams. An added row or column component must
  not silently change unrelated pixel or shot-noise draws.
- **Independent frames are a sufficient initial temporal model.** The plan
  makes AR behavior conditional on its introduction. Record iid frame order,
  seeds, repeat/reset/continuation behavior, and zero nonzero-lag covariance;
  do not claim flicker or a 1/f spectrum.
- **EI can be a metadata-only label**, explicitly leaving collected exposure,
  QE, full well and electronic gains unchanged. Use explicit seconds for
  exposure sweeps and explicit validated path configurations for gain sweeps.
  Do not introduce an undocumented ARRI EI-to-gain mapping.
- Reuse Phase 3 optics and sampling through a new structured spatial wrapper;
  preserve existing spatial schemas and their validation. A new outer bundle
  must identify new semantics instead of reusing an old format unchanged.
- Store enough component data for independent scalar checks of map slicing,
  deterministic expectations, total charge, well clipping, signed electronic
  sums, gain/black/round/clamp and observed merge. Hash checks alone are not
  adequate; a recomputed hash must not conceal changed physical semantics.

## Required independent checks

Deterministic oracles should cover identity, all four crop parities, non-square
maps, PRNU/exposure scaling, dark-rate scaling, zero exposure/rate, offsets at
both ADC rails, gain units, black offset applied once, total-charge saturation,
and electronic noise remaining signed beyond the physical well range.

Statistical checks should use predeclared sample-size tolerances for Poisson
mean/variance, common-shot covariance, row/column within-group covariance,
cross-path common versus independent terms, variance sums, temporal zero-lag
versus nonzero-lag behavior, and frame-difference variance twice the iid
single-frame variance. Include wrong-model controls for independent path shot
noise, offsets before well clipping, and black offsets counted twice.

Error checks must reject unknown fields, nonfinite values, negative rates/RMS,
bad shapes/identities/seeds and unsupported arithmetic before reporting a
successful result. Existing Poisson support is `[0, 1e9]`; PRNU/dark scaling
needs explicit overflow and lost-positive-support handling.

The full release retains **every Phase 1–3 numerical, real ISET, artifact,
runner-failure and fresh-process repeat gate**, as well as new Phase 4 gates.
Clean exact source and clean pinned dependencies are required at both ends;
dirty development runs must never become release acceptance. Reports require
commands, runtime, revisions, component provenance, counts and hashes, plus
observed CI results. Native MATLAB remains unverified until actually executed.

## Integration risks and handoff

- Creating this report makes the development checkout dirty. Parent confirmed
  baseline execution will use a separate clean worktree before production edits.
- The existing dual-gain path always draws both Gaussian arrays, including
  zero RMS; the single path draws only when RMS is positive. Direct disabled
  delegation avoids accidentally changing these established seeded contracts.
- Old spatial result validation expects baseline expected-charge semantics.
  Structured noise must have a new outer identity and validator rather than
  passing changed expectations through an unchanged old reader.
- All new defaults remain **assumed**, with declared temperature applicability.
  Measured imports, temperature laws, hot pixels, arbitrary covariance/AR
  models, rolling shutter, color transforms and calibration need not be added
  to satisfy the bounded initial Phase 4 implementation.
