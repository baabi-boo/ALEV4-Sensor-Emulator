## Implemented physics and compatibility

The six-argument API validates the supplied geometry and already-bound complete
single/dual readout through the existing geometry binder in `validate` mode.
It validates the separate noise model against the geometry's full grid. A
disabled model directly returns the corresponding legacy exposure result,
without adding wrapper fields or changing its RNG draws or arithmetic.

Enabled execution calls the existing spectral integration once. It retains that
baseline expectation, then applies achromatic PRNU and exposure-scaled dark
current. Photo and dark charge use separately named Poisson streams when their
respective switches are enabled. Each expectation is checked against the
sampler's `1e9`-electron maximum before either stream draws. Their sum is clipped
at one physical well, which both dual paths observe unchanged.

Shared fixed/row/column/frame electronics are added after the well. Path-specific
fixed/row/column/frame electronics and the existing per-pixel Gaussian read noise
follow. Row draws have one value per active row, column draws one per active
column, and frame draws one per frame. All are retained in input-referred
electrons. A component total is evaluated in fixed, row, column, frame, pixel
order; signed readout is `(stored + shared.total_e) + path.total_e`.

The existing DN/electron gain and black offset are each applied once, followed
by rounding and ADC clipping. Signed read electrons are never clipped to the
well or to zero. Conservative strict-interior ADC usability, rounded-code
clipping, physical saturation and reconstruction validity remain separate.
The dual merge receives only the recorded RAW channels and canonical readout
configuration through the unchanged `mergeDualGain` function.

`readout.expected_electrons` means total expected photo-plus-dark charge.
PRNU-scaled photocharge and dark charge are not subjected to an inappropriate
incident-photon upper bound. Dark signal can independently saturate the physical
well. Metadata explicitly says `parameter_classification='assumed'`,
`synthetic=true`, `calibrated_alev4=false`; the supplied reference temperature is
an applicability condition with no temperature law or extrapolation.

## Seed and numeric contracts

`structuredNoiseSeed(frame_seed, component)` consumes no randomness and accepts
only integer seeds from zero through `2^32-1`. The helper returns
`mod(frame_seed + tag, 2^32)`, exactly representable over the supported range.

| Component names | Tags |
| --- | --- |
| `photo`, `dark` | 1, 2 |
| `shared_row`, `shared_column`, `shared_frame` | 10, 11, 12 |
| `single_row`, `single_column`, `single_frame`, `single_pixel` | 20, 21, 22, 23 |
| `high_row`, `high_column`, `high_frame`, `high_pixel` | 30, 31, 32, 33 |
| `low_row`, `low_column`, `low_frame`, `low_pixel` | 40, 41, 42, 43 |

The entire exposure has an RNG cleanup guard. Each nonzero sampled component
additionally saves/restores a local Twister state. A zero component makes no
draw and cannot shift another stream; turning either shot switch off cannot
shift the other shot stream or any electronic stream. Adjacent seed values are
the synthetic reproducibility policy, not a claim of mathematical independence
or identical MATLAB/Octave streams.

The enabled implementation rejects finite-range overflow, nonzero subnormal
arithmetic in its retained expectations/components/readout operations, and
products whose nonzero support becomes zero. It also detects baseline
photo/incident support erased by spectral integration. Exact physically zero
exposure and zero fill factor preserve zero charge while still allowing signed
electronic offsets and noise. Its retained irradiance cube is limited to
100 million numeric samples, independently of the existing pixel limit.

## Remaining validation obligations

Dedicated Phase 4 suites should add finite-sample Poisson, row/column and
shared/path covariance checks, wrong-model controls, broader invalid-input and
boundary cases, full-grid/crop map identities, and independent sequence and
artifact reconstruction. The implementation is complete within this ownership
slice; release status remains for the coordinator's actual acceptance gates.

Resource-review follow-up: the enabled core currently rejects an input cube
above 100 million numeric samples before active-map extraction. It does not yet
budget the aggregate samples retained across maps, component planes, readout
planes and configuration copies. Default scalar maps can therefore expand to
many active planes even when the input alone meets its limit. The coordinator
requested this be handled by the later resource-review task; no conservative
aggregate-budget patch was added in this slice. Disabled support remains the
unchanged legacy contract.
