# Wave 1, agent C — artifact and acceptance design audit

## Work performed

Read `AGENTS.md`, `docs/PHASE4_PLAN.md`, `docs/ARCHITECTURE.md`, the Phase 3 artifact specification, native export/read/validation helpers, independent Python verifier, numerical runner, aggregate runner, and representative corruption/orchestration/failure tests. This is a design audit, not executed Phase 4 acceptance. No production code was changed.

## Main finding

Enabled structured noise requires a new format and algorithm identity. The Phase 3 exporter replays the legacy readout against its original spectral expectation; its reader independently associates that expectation with existing single/dual metadata. Passing altered charge or electronic offsets through unchanged `ALEV4-SYNTHETIC-SPATIAL` or legacy readout metadata would misstate the algorithm. Preserve old exports exactly for absent/disabled noise and reject enabled structured results in old exporters.

## Proposed practical Phase 4 bundle

Use a fresh directory with `noise.json`, `format=ALEV4-SYNTHETIC-NOISE`, schema `1.0`, and `algorithm_version=phase4-structured-noise-v1`. Freeze field names only after the core model/API contract is agreed. Retain explicit false calibration/ARRIRAW labels, little-endian row-major payload order, complete old readout configuration, geometry/ROI, exposure, sensor-realization identity, frame/sequence identity, component seeds, runtime and observed source/dependency provenance.

The manifest should include exact stage order, independent photo/dark shot-noise policy, PRNU normalization policy, temperature applicability, source classifications, and fixed versus temporal component lifetimes. A source identifier alone is not evidence of measured parameters. EI is a declared label/policy; it must not silently alter physical expectations.

Recommended fixed-name float64 payloads, with explicit descriptors and units:

- Full-grid PRNU multiplier and dark-rate maps, plus fixed electronic maps for each explicitly supported placement. Full-grid bytes allow map/ROI association to be independently checked. Keep demo grids small.
- Active baseline photo expectation, response-adjusted photo expectation, dark expectation, separately sampled photo/dark charge if those histories are part of the model, combined pre-well charge, and stored charge.
- Each supported signed electronic component, total signed readout per path, and mode-specific RAW planes. For dual mode retain merged electrons and explicit flags with observed-channel merge verification.
- For a spatial frontend, retain the actual optical/sample association or explicitly bind a separately verified baseline spatial bundle by content hashes. Do not claim spatial reconstruction from only a baseline expectation plane.

Each descriptor should reuse the Phase 3 exact `name`, `sha256`, `byte_count`, `sample_type`, `shape`, and `units` vocabulary. Shape is an explicit vector, including singleton dimensions. No manifest-controlled relative paths. Validate exact inventory, bounded byte counts and actual reads, finite values with signedness appropriate to the component, distinct regular files, and nonaliased demo/repeat roots.

Native reader and exporter must independently validate full struct associations. An exportable result is mutable; fields and success flags alone prove nothing. Write to an exclusively owned staging directory, verify it, publish the manifest last, refuse existing targets, and clean up only owned output.

## Semantic verification requirements

The Python verifier should independently calculate:

1. ROI slices of persistent full-grid maps and preservation of full-grid coordinates/CFA binding.
2. `expected_photo = baseline_expected * response_multiplier` and `expected_dark = dark_rate * exposure`, with collection area/fill/QE already included exactly once by the baseline.
3. The recorded component sum, one common physical full-well clipping operation, and saturation flags.
4. Signed electronic offsets/noise added after the well; black offset applied once in DN, gain applied in DN/electron, and rounding/clipping performed at the ADC.
5. Dual merge and usability flags from observed RAW/configuration only; retained truth arrays cannot enter reconstruction.
6. Fixed per-row/per-column component association and repeated-map identity. For arbitrary stochastic draws the verifier can check declared algebra and observable constraints, not prove the random-stream distribution. Numerical statistical tests and fresh-process repeats supply that separate evidence.

Use scale/operation-count ULP comparisons referenced to the expected value, retaining exact zero/nonzero requirements. A changed payload must never widen its own tolerance. Corruption tests must recompute SHA-256 after changing charge, map crops, units/stage placement, component sums, rails, and flags so semantic validation is tested independently of hashes. Include unknown/duplicate JSON fields, scalar-versus-vector wire types, nonfinite/subnormal values, extra/truncated bytes, symlinks/hardlinks, and producer-result mutations.

## Existing reusable implementation

- `spatialBundleUtil`: field/type/bound validation, exact-token JSON, row/plane binary I/O, hashes, regular/distinct paths, portable keyed lists, runtime/provenance equality, and scale-aware arithmetic comparison.
- `spatialDecodeJson` and `encodeBundleJson`: preserve coordinates exactly and enforce the established bounded portable wire vocabulary; do not replace them with native JSON decode for geometry.
- Python `verify_phase3_artifacts`: `read_json`, `bounded`, `regular`, `directory_path`, `fields`, `shape`, `_file`, `config`, `geometry`, `runtime`, `provenance`, `arithmetic_close`, and independent spectral/geometry utilities.
- Python Phase 2 verifier: observed dual merge/rail semantics. Reuse those calculations without inventing a legacy manifest for enabled Phase 4 behavior.
- `run_phase3_acceptance`: clean-source/dependency snapshots, isolated Git environment, logged subprocess exits, disjoint fresh-process repeat file identities, and full receipt hashes.

Avoid extracting/refactoring preserved utilities merely for tidiness during this phase; small new wrappers/imports keep legacy regression risk low.

## Aggregate acceptance proposal

A new `run_phase4_tests` should invalidate stale success first, require explicitly enumerated Phase 4 suites and complete Phase 3 numerical prerequisites, and remain `core_only`/not accepted when prerequisites are disabled. Add real failure-injection tests for skipped/missing/malformed suite reports, failed report writes, and errors after return.

A new `run_phase4_acceptance.py` can follow the existing Phase 3 orchestration with one additional nested prerequisite level: execute `run_phase4_tests(..., true)`, run failure controls for phases 1–4, generate four phases' demos and repeats in separate numerical processes, copy nested prior numerical reports to their established verifier layouts, invoke all four independent artifact verifiers, and check clean exact source/dependencies before and after. Preserve all existing entrypoints/workflows and add `master` to CI push branches because it is the requested delivery branch.

An alternative is to execute the complete existing Phase 3 aggregate as a child gate, then Phase 4 core gates, but the new top-level validator must deliberately distinguish that from standalone core acceptance and prove that the complete child receipt passed at the identical source/runtime. Do not accidentally run old gates twice unless needed to resolve a concrete risk.

Retain new output-root refusal, `--development` always setting `release_accepted=false`, full expected commit checks, Git index hidden-change checks, failure receipts, unchanged source at end, and every actual command/exit/hash. Unit tests of the orchestrator are fixture-only control-flow evidence and must remain labelled that way. A phase completion document must identify the exact tested implementation revision separately from subsequent evidence-only commits, and native MATLAB remains unverified until run.

## Outstanding implementation decisions

The artifact inventory depends on whether the core supports independent frames only, correlated temporal state, shared versus path-specific electronics, and arbitrary measured-map imports. Freeze that scope first. Recording unsupported fields without an executed model would create ambiguous or unverifiable semantics. Small explicit deterministic maps and independent frames can satisfy a well-documented first implementation; claims about flicker/1/f, sensor calibration, or native MATLAB cannot follow from these generic artifacts.
