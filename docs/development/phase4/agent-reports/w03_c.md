# Wave 03 agent C: independent Python structured-artifact verifier

## Implementation and interfaces

Implemented only `scripts/verify_phase4_artifacts.py` and this report. No Git
mutation, dependency edit, other agent's file edit, or further delegation was
performed. Coordinated the frozen wire directly with agent B and the numerical
runner inventory with the coordinator. Read the repository working rules,
architecture/roadmap, Phase 4 design, and the Wave 02 core/wrapper/demo reports.

The verifier uses only Python's standard library. It never invokes MATLAB or
Octave, executes a simulator, or reproduces a random stream. Its public entry
points are:

- `verify_bundle(directory, expected_commit=None)` returns the decoded `result`,
  original manifest under `metadata`, normalized scalar `configuration` and
  `sensor`, `source`, `runtime`, `files`, exposure/seed, and check-boundary flags.
  Numeric result leaves use `Array` with `class_name`, `shape`, C-order `values`,
  `units` and `offset`. Cell and character nodes retain their native shape.
  `plain(result)` converts typed values to MATLAB JSON-compatible summary values.
- `verify_demo(directory, source=None, engine=None)` returns the exact 49-file
  inventory and independently calculated metrics for all 24 frozen fixtures.
- `verify_outputs(output_root, expected_commit=None, compare_dir=None)` requires
  full numerical prerequisites and optionally verifies a byte-identical repeat
  with disjoint file identities. Its CLI accepts `--expected-commit` and
  `--compare-dir`.

Strict wire checks cover exact file entries and manifest/node fields, duplicate
or nonportable JSON keys, bounded UTF-8 JSON/nesting/tree size, canonical native
shapes/classes, finite little-endian numeric samples, C row-major ordering,
contiguous original-field/cell-linear depth-first payload offsets, aggregate
sample/byte accounting, exact path-derived units, logical bytes, the entire
payload SHA-256, ordinary non-symlink ancestors, and single-link files. Character
extents follow the recorded runtime: UTF-8 bytes for GNU Octave and UTF-16 units
for MATLAB. Character payloads are rows or bounded empties, with no NUL.

Semantic checks independently validate configuration and geometry/CFA binding,
the complete explicit full-grid noise model, exact active-map crops, component
seed tags, order, units, classification and temperature metadata. Scalar math
reconstructs spectral incident/photo expectations, PRNU and dark expectations,
recorded photo/dark charge assembly, one physical well, shared/path electronics,
signed readouts, half-away-from-zero rounding, ADC clipping/usability, and the
observed-channel merge with separate physical reconstruction validity.

Spatial bundles retain their complete legacy baseline. Its input, PSF, optical
field, conservative footprint average, reports/diagnostic integrals and legacy
analog/ADC/merge history are checked. Earlier independent Python scalar optics,
sampling, configuration and observed-merge helpers are reused with an explicit
C-order-to-spectral-plane conversion; no native implementation is called.

The demo verifier independently freezes each analytical fixture's full
configuration, full maps, source identifiers, irradiance, exposure and seed. It
reconstructs summary counts/statistics, all four sweeps, three sequence calls,
seed wrap, complete reset/continuation frame equality and EI-only metadata.
Producer completion/coverage flags are checked against these calculations.

## Boundaries and pending acceptance

The nine mandatory numerical suite keys are frozen as `config`, `core`, `noise`,
`rng`, `sequence`, `spatial`, `artifact_io`, `demo_contract`, and
`numerical_edges`. Currently each requires a passed status, positive count,
count-matched inventory, unique nonempty test names, and all individual passed
statuses. **Individual group names/counts are not yet frozen.** Wave 04 should
freeze those inventories after all nine suites exist. Full nested Phase 3/2/1
reports, exact runtime/source association and frozen dependency pins are required.

`verify_outputs` is implemented but was not exercised against a complete Phase 4
numerical report or an independent fresh-process repeat in this task; those
artifacts did not yet exist. Full preserved acceptance, permanent corruption
tests, runner failure controls, clean source/dependency verification, release CI,
and native MATLAB execution remain pending. The observed development source
HEAD was `be5226f45c8a7dbe7dbd7946ffcd302f6337bc96` with concurrent uncommitted
work; these results are not evidence of clean release execution.

Finite random samples are checked for declared Poisson support, exact zero-mean
and zero-RMS constraints, and deterministic downstream consistency. Such checks
cannot authenticate a PRNG realization, establish a distribution or independent
frames, prove numerical execution from a JSON report, authenticate input/source
claims, or establish measured ALEV4 calibration. Those boundaries are explicit
in returned verification records.
