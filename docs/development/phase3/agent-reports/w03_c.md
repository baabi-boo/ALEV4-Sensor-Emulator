# Wave 3 C — native spatial bundles (assignment 15/60)

## Scope and implementation

Implemented only these Phase 3 production files under `matlab/+alev4/`:

- `exportSpatialBundle.m`
- `readSpatialBundle.m`
- `spatialBundleUtil.m`
- `spatialValidateResult.m`
- `spatialDecodeJson.m`

The writer and reader follow `docs/PHASE3_ARTIFACTS.md`: fixed file inventory,
SHA-256 and exact lengths, little-endian plane-major/row-major float64 arrays,
strict keyed source/operation lists, complete geometry and readout settings,
PSF metadata and coefficient association, original/intermediate/expected data,
and unchanged nested Phase 1 or Phase 2 formats. No shared legacy serializer,
readout, dependency, test, workflow, or documentation file was edited by this
assignment. No subagents were spawned.

The exporter recomputes optics, overlap averages and spectral charge, then
replays the complete seeded readout in the current runtime before staging.
It refuses existing paths, creates an owned staging directory, writes the
manifest last, verifies the staged bundle, and publishes only after another
absence check. Owned cleanup failures warn explicitly. A post-move check
rejects accidental directory nesting caused by a racing destination and removes
only the owned nested staging directory; concurrent writers remain unsupported.

The reader checks strict JSON, exact fields, fixed names, units, shapes,
lengths, hashes, file inventory and identity before interpreting payloads.
It recomputes spatial/spectral association and checks unchanged nested readout
metadata against the outer configuration, runtime, exposure, seed and source.
Deterministic codes are checked against expected charge; noisy analog history
is not inferred. Dual merging remains exclusively based on recorded channels.
Both public functions explicitly restore caller RNG on success and failure.

File identity is mandatory: GNU Octave uses `lstat`; MATLAB uses JVM
`Files.isSymbolicLink` and `Files.isSameFile`. Hashing uses Octave's built-in
SHA-256 or MATLAB JVM MessageDigest. Missing capability is an explicit error.
Native MATLAB execution remains unverified. No Python runtime dependency was
introduced into native bundle I/O.

## Coordinate JSON defect found during integration

Root and the demo agent found that the shared native JSON decoder rounded the
17-digit token for `7*6e-6` down by one ULP. The original binary64 value is
`3f06052502eec7ca`; native JSON returned `3f06052502eec7c9`. Exact coverage then
correctly rejected an apparently undersized source grid in `shifted_impulse`.

Added Phase 3-only `spatialDecodeJson`: first run the existing strict decoder
for JSON grammar, duplicate/escaped key aliases, depth, field limits and finite
range; then recursively reconstruct numbers from their original tokens using
`str2double`. Native escape decoding remains in use for strings. Nonzero tokens
that underflow binary64 are rejected. Numeric vectors and matrix rows retain
portable shapes. **No coordinate was snapped and no coverage tolerance was
loosened.** The existing Phase 1/2 encoder and decoder remain untouched.

## Native API details

`files = exportSpatialBundle(directory,result)` returns `.directory` and
`.metadata`. `[decoded,meta] = readSpatialBundle(directory)` returns checked
arrays and canonical native metadata (source/order lists decoded into cells,
normalized configuration and PSF including coefficients). For noisy data,
`decoded.readout` contains recorded/observable fields plus retained expected
charge and recomputed incident photons, not a fabricated complete analog
history. This decoded object is not promised to be re-exportable as a full
original simulation result.
