## Claim-to-code checks

### Geometry, source IDs, cropping, and CFA

`alexa35Geometry` supplies only the Open Gate count/pitch and a chosen coordinate origin. It requires the caller's Bayer pattern and labels the optional ROI as experimental. There is no default implicit ARRI CFA phase in this API. `sensorGrid` shifts the complete Bayer tile by the one-based ROI offset; the usage example's RGGB-to-BGGR result at row 2, column 2 matches that implementation.

The profile's three IDs resolve in the register: `ARRI-A35-GEOMETRY`, `DERIVED-A35-EXTENT`, and `ASSUMED-CFA-ORIGIN`. The generic geometry, discrete PSF, and ISET constructor IDs also resolve. The register separately documents QE, rectangular aperture, and source-cell assumptions; these are not manufacturer measurements.

Source-ID validation checks syntax/uniqueness rather than authenticating a citation or constraining all parameter values to a particular record. The artifact documentation already states that source IDs are provenance claims and that exact-source/dependency checks are separate. I found no contrary promise of automatic source authentication.

The published grid is explicitly restricted to the modeled Open Gate area. README, usage, and source register do not infer total silicon dimensions, optical-black sites, actual smaller-mode crop origins, measured QE, or electronic parameters from it.

### ISET semantics

The restricted fixture obtains the already computed optical field, declares `post_optics`, and supplies no second project PSF. Its chosen 16 × 16 full-fill square sensor checks the geometry required for the native 1 × 1 prefilter. It reads native spectral response and returned CFA order and deliberately requires the RGGB fixture it requested; this is not a claim about ARRI hardware.

`isetPointGrid` uses explicit bilinear reconstruction, retains interior native knots in the cell boundaries, uses the mean of each cell's four reconstructed corners, and rejects extrapolation. For a bilinear patch, that corner mean equals the cell integral divided by area. The documented conversion therefore describes the implemented mathematical model rather than simply relabelling native points as averages.

The adapter compares fractional electrons, independently integrates the bilinear field, and records separate native/source refinement errors. Those are implementation facts inspected here, not fresh measured pass results from this audit.

### PSF/MTF provenance and scope

`createOpticalPsf` labels its finite nonnegative kernel as synthetic; the source register uses `ASSUMED-DISCRETE-PSF`. `applyOpticalPsf` performs pre-CFA spectral convolution with complete-support cropping. `opticalMtf` directly sums the finite kernel with its declared spacing and origin and returns the complex transfer and magnitude. The optional square-aperture sinc is explicitly a continuous analytical reference.

The root also clarified PHASE3_DESIGN's unit-mass tolerance, `32 * coefficient_count * eps(1)`, and the absence of renormalization. This matches the inspected constructor. No external measured ARRI PSF, OLPF, or lens-transfer source is claimed, and none is needed to define this explicitly synthetic discrete operator. The analytical definition and code supply the method provenance; they cannot establish camera calibration.

### Sensor identity, dynamic range, and file-format claims

README and the reviewed Phase 3 documents explicitly exclude calibrated ALEV4 equivalence, demonstrated 17-stop performance, and genuine ARRIRAW. The emitted spatial/optical reports label data synthetic and uncalibrated, and the spatial manifest declares `authentic_arriraw=false`. I found no conflicting affirmative sensor-identity, measured-dynamic-range, or real-ARRIRAW claim in the reviewed scope.
