## Validator contract

The validator requires an explicit completed count. Prefix mode accepts an
assignment ledger extending beyond that archived count and does not require
originals from still-pending tasks. It nevertheless checks uniqueness and
canonical ordinal/wave/report/task identities for every recorded assignment.
The final `--expected 60` mode requires all of the following:

- Exactly 60 unique assignments and 60 completed index entries, ordered by
  contiguous ordinal, with exactly six entries in each wave 1–10.
- Exact index schema fields, correctly typed values, `requested_agents=60`,
  `requested_waves=10`, `completed_agents=60`, and `status="completed"`.
- Exact task metadata fields, `status="completed"`, matching recorded task
  identity, and the expected `agent-reports/wXX_letter.md` path for each ordinal.
- Exact archived inventory and exact final original Markdown-report inventory;
  no missing or extra paths, directories in the flat archive, or symlink report
  files. All archived reports must be nonempty UTF-8.
- Actual archived byte counts and SHA-256 values matching the index, and actual
  original bytes matching either the byte-identical declaration or the exact
  declared terminal-LF removal with original byte count/hash. Adding a final
  newline to a report that lacked one, changing CRLF conventions, or changing
  an interior byte is rejected under that declaration.
- Exactly 60 Markdown rows, with matching ordinals, waves, canonical tasks,
  report labels and relative links; no extra report links; one index link;
  and the explicit Markdown `completed` status.

Duplicate JSON keys, unrecognized fields, wrong scalar types such as Boolean
values in integer fields, and nonstandard JSON numeric constants are rejected.
The validator reads files and emits one concise JSON result to stdout. It does
not modify the repository or source reports. Successful output includes checked
counts, wave counts, normalization names, index/ledger digests and the two report
inventory digests. A detected inconsistency returns exit status 1 and JSON with
the reason. `--workspace` and `--repo` can select relocated source directories.
