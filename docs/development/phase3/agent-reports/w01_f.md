# Wave 1 F — restricted nonuniform ISETCam comparison design

## Scope

Read AGENTS.md, Phase 3 design/plan and the existing uniform adapter. Inspected
the pinned ISETCam functions below. No repository production files were edited.
An exploratory script and logs are in this report directory; they are not
release evidence and must not be presented as accepted Phase 3 gates.

## Native semantics and a critical extra operation

At pin `3e0253421752eb72f2d1353327dffd0d433abdaf`:

- `opticalimage/oiSpatialSupport.m` explicitly describes **sample points**.
  The positions are centered about zero: columns span
  `-(W-1)*dx/2` through `+(W-1)*dx/2`; rows follow the same convention.
- `opticalimage/oiGet.m` exposes these coordinates through
  `spatial support linear`, and spacing through `distance per sample`.
  The latter is [row spacing, column spacing] in metres.
- `sensor/simulation/sensorCompute.m` calls `signalCurrent`, then applies
  exposure and volts/electron conversion; `volts / conversion gain` is the
  fractional-electron reference. Disable autoexposure/noise/vignetting, use
  analog output and unity gain/zero offset, and keep below voltage swing.
- `sensor/simulation/SignalCurrentDensity.m` multiplies photon density by
  spectral QE and wavelength bin width. It performs part of its arithmetic
  in single precision, so retain a small separately identified rounding bound.
- `sensor/simulation/signalCurrent.m` derives gridSpacing as the reciprocal
  of `sensorGet(sensor,'nSamplesPerPixel')`.
- `sensor/simulation/spatialIntegration.m` defaults to bilinear interpolation
  at one point per pixel. Odd supersampling counts perform midpoint quadrature
  over a pixel and include the photodetector-area mask.
- **`sensor/simulation/regridOI2ISA.m` unconditionally applies a Gaussian
  prefilter** before `interp2(...,'linear')`. Its support is
  `[ceil(pixel_height/dy),ceil(pixel_width/dx)]`, with sigma one quarter the
  first ratio. This is not the project's exact box-average sampler. Comparing
  unmodified fine OI values to this reference would mix two aperture models.
- `utility/units/sample2space.m` centers point positions by their arithmetic
  mean. Sensor subpixel midpoints therefore share the physical origin above.
- `sensor/sensorPDArray.m` is marked as requiring checking. Restrict to ideal
  square pixels with fill factor one so this legacy subpixel aperture mask
  stays an all-ones matrix; do not claim general fill-factor agreement.

## Recommended supported fixture

Use genuine `sceneCreate('uniformEqualPhoton',[32 32])`, multiply its spectral
photon data by a known nonnegative achromatic uniform/ramp/checker/edge pattern,
then execute `oiCompute` with off-axis loss disabled and explicit mean padding.
Use the returned photons/support/spectral data, not the original input pattern,
as the post-optics reference. The diffraction optics can transform the pattern;
that transformation is already present and must not receive the standalone PSF.

Choose FOV by inspecting **actual** returned spacing, not an assumed focal
length. For the current default optic, a 0.25-degree trial returned spacing
0.5284 micrometres, much smaller than 5-micrometre sensor pixels. That trial is
outside the proposed contract and is not a passing comparison. A 3-degree
trial is being checked as a useful small starting point. Required conditions:

1. `dx >= pixel_width` and `dy >= pixel_height`, with a representable margin;
   then ISET's prefilter is exactly 1x1, without modifying upstream source.
2. Every sensor pixel **footprint**, not just its center, lies within the OI
   point-support rectangle. Do not inherit ISET's outside-coverage NaN-to-zero
   behavior as a successful optical comparison.
3. Full fill factor; square 5-micrometre pixels; centered 16x16 sensor (actual
   returned dimensions verified); RGGB checked against ISET's returned tile;
   matched wavelengths/bin widths and imported effective RGB QE.
4. The photocharge comparison is noiseless and before quantization/clipping.

## Point samples to declared cell averages

Define the optical image as a **bilinear reconstruction of its point samples**
inside their convex rectangular support, with no extrapolation. Construct a
finer edge grid by subdividing each interval between original point knots.
Every new rectangular cell lies within one bilinear patch. Its exact average
is the mean of the interpolated field at its four corners. These are legitimate
cell-average irradiances, not relabelled original point values. State the
reconstruction explicitly and hash/store original point samples plus support.

The project's conservative sampler then integrates the piecewise-constant
approximation formed by these averages. Refine by factors 1, 2, 4, 8, etc.
Any target boundary that splits a new source cell introduces the stated
piecewise-constant approximation; errors should decrease under refinement.
An exact independent reference can split each pixel rectangle at original
point knot lines. On each intersection, mean the four bilinear corner values
and multiply by intersection area. Sum those pieces: this exactly integrates
the bilinear reconstruction without using the production overlap sampler.

## Native comparison and convergence

For the same OI, execute genuine `sensorCompute` with odd
`nSamplesPerPixel = 1,3,9,27` (or a smaller justified sequence after timing).
Default n=1 is midpoint sampling, not an exact box integral around a knot.
Increasing n should converge to the independently integrated bilinear field.
Compare both the project cell-refinement sequence and the ISET subpixel
sequence against that common analytical reference. This separates:

- optics: both consume the same actual `oiCompute` output;
- spectral response: identical imported bins/QE, with measured roundoff bound;
- sample reconstruction: explicitly bilinear;
- pixel integration: exact bilinear integral versus two stated approximations.

Uniform and affine ramp regions should agree down to the single-precision
upstream roundoff. Edge/checker cases crossing OI knots need a quadrature
bound. For a bounded piecewise-linear field, midpoint error near a derivative
break falls with subpixel width. Set tolerances from the independent analytical
integral and convergence sequence, not visual similarity. A high-resolution
reference alone is not an independent exact oracle.

## Implementation proposal

`[result,cfg,report] = alev4.isetSpatialFixture(kind, refinement, seed,
exposure_s)` with supported kinds exactly `uniform`, `ramp`, `checker`, `edge`.
Keep the adapter purpose-built, not an arbitrary-scene importer. Expose either
the conversion helper or record its source/output grids and cell-average data
in the report so acceptance can independently verify it. The report includes
native point-support geometry, native OI hashes, reconstruction convention,
actual optical settings, no-additional-PSF operation order, quadrature count,
refinement factors, analytical integral, native comparisons, and source pins.

Preserve caller RNG, vcSESSION, and ISET preferences using the same guards as
`isetBaseline`. Reject unsupported scenes, absent dependencies, coverage gaps,
nonuniform/singular native grids, spectral mismatch, nonfinite samples, sensor
clipping, or prefilter-size >1. Preserve the existing uniform gate separately.

## Status

The corrected covered-support exploratory run completed in GNU Octave 9.4.0
with genuine `oiCompute` and `sensorCompute`. At scene FOV 3 degrees, returned
OI spacing was 6.34227819 micrometres (both axes), greater than 5-micrometre
pixel pitch; fill factor was one. Maximum absolute electron disagreement,
normalized by the maximum exact-reference electrons, was:

| Fixture | Native n=1 | n=3 | n=9 | n=27 |
| --- | --- | --- | --- | --- |
| uniform | 1.53e-7 | 1.95e-7 | 6.18e-7 | 1.62e-6 |
| ramp | 3.17e-5 | 4.32e-6 | 5.07e-7 | 1.15e-6 |
| checker | 8.09e-2 | 4.33e-3 | 5.24e-4 | 9.16e-6 |
| edge | 3.48e-2 | 2.74e-4 | 2.74e-4 | 6.25e-6 |

Thus a 5e-5 final relative threshold at n=27 is experimentally plausible for
these **fixed** fixtures and includes upstream single-precision accumulation.
Do not assert strict monotonicity at every refinement: grid alignment can
produce plateaus, and roundoff dominates the smooth cases. Require convergence
from the coarse wrong-model controls and independently compute each residual.
The exploratory script is `iset_probe.m`, and the successful log is
`iset_probe_covered.log`. The earlier unsupported small-FOV run is explicitly
excluded. These temporary probes are reproducible design evidence only.

This is a source-informed design and exploration, not an implemented or
accepted adapter. The production implementation must execute and retain the
comparison/convergence gates before declaring Slice 3D complete. Native MATLAB
and measured ARRI optical/spectral response remain unverified.
