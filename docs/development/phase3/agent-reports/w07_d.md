## New finding: index flags can conceal changed source

Both the initial and final release checks currently rely on:

```text
git status --porcelain=v1 --untracked-files=all --ignore-submodules=none
```

Stripping inherited `GIT_*` variables prevents the previously reported
environment redirection. It does not remove persistent `assume-unchanged` or
`skip-worktree` flags from the repository's index. These flags cause the
reviewed status query to return empty for a changed tracked file.

In two separate controls inside an owned temporary local clone, the audit:

1. Read the original bytes of `matlab/+alev4/createBaselineSensor.m`.
2. Applied either `git update-index --assume-unchanged FILE` or
   `git update-index --skip-worktree FILE`.
3. Appended an uncommitted MATLAB comment to that tracked source file.
4. Called the production `runner.git()` helper with the exact status query.
5. Confirmed that the actual file bytes differed from HEAD while the helper
   returned an empty status string.

The real index tags were `h` for assume-unchanged and `S` for skip-worktree.
No new commit was needed. The source revision remained the existing HEAD.
The direct results are retained in `w07_d_index-flags.json`.

The audit then exercised the actual `execute()` function with real Git reads
and artificial zero-exit external gates. Both changed-source cases completed
the 16-command orchestration and produced these incorrect source/release
predicates:

| Case | Actual source differs from HEAD | Clean at start | Clean at end | Aggregate status | Release accepted |
| --- | --- | --- | --- | --- | --- |
| `--assume-unchanged` | true | true | true | `passed` | true |
| `--skip-worktree` | true | true | true | `passed` | true |

These are **mock-gate orchestration reproductions**, not numerical execution
or a genuine release pass. Their relevance is the false-cleanliness predicate
and resulting release flag. Exact retained rows, including the 16 mocked
commands, are in `w07_d_index-receipts.json`.

A minimal local reproduction of the Git condition, after cloning into an
owned temporary fixture and setting `FIXTURE_REPO` to that clone, is:

```bash
git -C "$FIXTURE_REPO" update-index --assume-unchanged matlab/+alev4/createBaselineSensor.m
python3 - "$FIXTURE_REPO" <<'PY'
from pathlib import Path
import sys
path = Path(sys.argv[1]) / 'matlab/+alev4/createBaselineSensor.m'
path.write_bytes(path.read_bytes() + b'\n% Uncommitted acceptance-source audit mutation.\n')
PY
git -C "$FIXTURE_REPO" status --porcelain=v1 --untracked-files=all --ignore-submodules=none
git -C "$FIXTURE_REPO" ls-files -v matlab/+alev4/createBaselineSensor.m
```

The status output is empty; `ls-files` identifies the `h` flag. An independent
fresh control with `--skip-worktree` gives the same empty status and the `S`
flag. The audit itself created and removed all such fixtures automatically.

Suggested closure for the owner: either reject source-hiding index flags for
release checks before and after execution, or verify indexed tracked content
against HEAD through a method that does not trust those flags. The final
source check needs the same protection as the initial check because flags can
be set during the gated run. This assignment leaves that implementation and
its regression tests to the root's designated owner.

### Recursive coverage decision

A bounded real-Git probe with an initialized dependency and initialized nested
dependency established that:

```text
git ls-files -v --recurse-submodules -z
```

does recurse into tracked files but omits the gitlink entries themselves. It
therefore missed a flagged root gitlink and a flagged nested gitlink in that
fixture. The retained probe is `w07_d_recursive-index-probe.json`.

The implemented scan instead combines:

```text
git ls-files -v -z
git submodule foreach --quiet --recursive "git ls-files -v -z"
```

The first command covers the root index, including its gitlinks. The fixed
foreach command covers every initialized recursive submodule's own index,
including nested gitlinks. NUL separation preserves record boundaries. These
are internal Git reads through the existing isolated environment helper; the
**16 external acceptance gates remain unchanged**. The preserved
`verify_submodules.py` was not modified.
