## Interfaces and contract

- `createOpticalPsf(overrides)`: schema 1.0, kernel, explicit origin_rc,
  spacing_yx_m, wavelength_nm, boundary_policy='valid', parameter_sources.
  A nontrivial kernel override requires origin_rc. Kernel weights are finite
  nonnegative dense doubles, at most 63 by 63 and one million total values.
  Each plane must sum to one within 32*H*W*eps(1); coefficients are not modified
  or renormalized on revalidation. Empty wavelengths denote one shared kernel;
  otherwise every kernel plane has a positive increasing explicit wavelength.
- `[filtered,grid,report]=applyOpticalPsf(input,grid,psf,wavelength_nm)`: uses
  the new shared spatial validator, verifies uniform cells and physical spacing,
  exact spectral association, and complete declared kernel support. No RNG,
  CFA, area, exposure, or spectral weighting. Identity returns exact input.
  Origin-dependent crop follows rows h-or+1:H-or+1 and columns w-oc+1:W-oc+1.
  Even/asymmetric kernels retain correct convolution direction and grid origin.
  Grid tolerance accounts for edge-coordinate subtraction, without a metre-sized
  floor; badly resolved coordinates (tolerance >= spacing/1024) reject. Numeric
  overflow or total underflow of a positive supported output rejects.
- `report=opticalMtf(psf,fx,fy,pixel_pitch_m)`: direct complex finite DFT,
  frequency vectors in cycles/metre, principal Nyquist bounds, explicit kernel
  phase/origin and optical magnitude. Optional continuous square-aperture sinc
  is separate and labelled as an analytical reference; it does not claim the
  measured response of the cell-average overlap sampler. Maximum output is
  one million frequency samples across kernel planes.

Apply reports include kernel shape, spacing, origin, original retained index
ranges, required halo [top bottom left right], input/output shapes, density
units, normalization policy, and synthetic/calibration labels. MTF reports
include optical_otf, optical_mtf, physical frequency vectors, Nyquist axes,
finite support, and optional pixel_aperture_otf/pixel_aperture_mtf plus
optical_times_continuous_aperture_mtf. Complex OTF data need explicit real/imaginary
conversion if a later JSON report exports them.
