## Findings resolved by root

### 1. Global normalization erased or distorted a finite constant crop

```matlab
small = realmax*eps(0);
points = [realmax small small; realmax small small];
actual = alev4.isetPointGrid(points,[0 1 2],[0 1],[1 2],[0 1]);
```

The requested crop is identically `small = 8.881784197001251e-16`, a normal binary64 value. Before the fix, the helper returned **0**. With `small = realmax*(3*eps(0))`, it returned `3.552713678800501e-15` instead of `2.664535259100375e-15`, a 33% error. Global normalization created positive subnormal values that were erased or rounded badly when corner values were divided by four.

Root added explicit numeric-range checks for positive normalized samples, interpolated corners, and normalized averages below the normal precision range. Regression cases cover both spatial orientations and require the independent constant-field answer or exactly `ALEV4:ISETPointNumericRange`.

### 2. A positive interpolation fraction rounded to zero

```matlab
p = 2^500;
width = 2^-575;
points = [0 realmax; 0 realmax];
actual = alev4.isetPointGrid(points,[0 p],[0 p],[0 width],[0 p]);
expected = (realmax/p)*(width/2);
```

The field is a linear ramp. Its exact cell average is `2.220446049250313e-16`, computed in a safe multiplication order. Before the coordinate fix, the helper returned **0**, including after the normalization/corner guards had been added: the interpolation fraction `width/p` itself rounded to zero, leaving no positive corner for the later guards to inspect.

Root added `checkFractions` before interpolation. Interior edges must retain normal, positive fractions to both enclosing knots and must not round to either endpoint. Exact native knots bypass this check. Regressions cover `width = 2^-574` and `2^-575`, both orientations, and require the correct finite ramp average or exactly `ALEV4:ISETPointNumericRange`.
