## Confirmed bugs and implemented fixes

### 1. Escaped NUL discarded original key or string spelling

The native JSON decoder truncated strings at an embedded NUL. As a result, `{"v\u0000":1}` became field `v`, and full valid bundles were accepted after changing:

- Outer `"seed":8301` to `"seed\u0000evil":8301`.
- Outer format string to `"ALEV4-SYNTHETIC-SPATIAL\u0000evil"`.
- Nested readout seed key to `"seed\u0000evil"`, with its descriptor hash and size refreshed.

`spatialDecodeJson` now preflights original quoted strings **before** invoking the shared decoder. It rejects raw or escaped NUL and unpaired Unicode surrogates. Literal text `"\\u0000"` remains supported, as do valid surrogate pairs. All three full-bundle bypasses have regression cases.

The same pass freezes Phase 3 object keys to ASCII `[A-Za-z][A-Za-z0-9_]{0,62}`, at most 63 characters, excluding the agreed 41-entry supported keyword union. The keyword list was checked against actual `iskeyword()` output from the 9.4.0 executable and coordinated with Agent 6b's Python verifier. Contextual words `enumeration`, `events`, `methods`, `properties`, and `arguments` remain valid controls. The existing shared strict decoder still enforces duplicate aliases, 256 fields per object, and 64 containers; exact scalar/vector/matrix depth boundaries are tested.

Legacy `decodeBundleJson.m` and `encodeBundleJson.m` are unchanged.

### 2. Numeric arrays lost their original container type

The old recursive array parser collapsed singleton arrays to scalar doubles before deciding parent array shape. It therefore admitted scalar fields written as `[8301]` or `[[[0.01]]]`, a descriptor shape written as `[[[6]],[[8]],[[2]]]`, a byte count `[8]`, and ragged informational metadata `[1,[2]]`.

The Phase 3 decoder now provides an optional compact kind tree. Numbers, vectors, matrices, empty arrays, booleans, text, and object fields retain their original JSON category. The parser rejects mixed arrays, nonnumeric arrays, ragged numeric rows, and arrays with rank above two before collapsing any singleton representation.

`readSpatialBundle` uses those original kinds to enforce schema numeric scalars and flat vectors for top-level values, geometry, grids, sensor/dual configuration, PSF coordinates and spectral mapping, descriptors, and nested single/dual metadata. It validates initial nested metadata before the legacy reader can normalize or overwrite it. Explicit arrays of booleans, including `synthetic:[true]` and `shot_noise:[false]`, reject.

Supported one-bin wavelength/bin-width scalar or one-element vector forms remain accepted. Single-bin QE still supports a flat RGB row or a one-row RGB matrix. General singleton numeric matrices and columns remain supported, with their original matrix type recorded. Exact numeric conversion remains `str2double` applied to original lexemes; coordinate boundaries are not snapped or relaxed.

### 3. Nested single-gain description lacked value validation

The top-level field inventory required `description`, but the legacy reader did not inspect it. Rehashed nested manifests with `description=17`, `description=""`, or `description="a\u0000b"` were accepted.

The Phase 3 wrapper now requires the initial nested single-gain description to be a nonempty, nonblank character row without NUL before calling the unchanged legacy reader. Regressions cover numeric, empty, blank, boolean and empty-array descriptions; original escaped-NUL rejection also applies to description strings.

### 4. Successful read-close errors were ignored

Agent 6c's probe shadowed `fclose` to physically close an input handle and then return `-1`; the old reader returned success because cleanup used only `closeQuietly`.

`spatialBundleUtil` now checks the explicit close status after successful manifest reads, payload reads and hashes, reporting `ALEV4:SpatialReadFailed` on failure. Cleanup guards remain for earlier exceptions. Four injected scenarios cover direct manifest/hash/payload reads and the complete reader; all verify preserved RNG state and file descriptor inventory. No legacy Phase 1/2 reader code was changed.
