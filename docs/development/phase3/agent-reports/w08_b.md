## Connector publication risks and required controls

The available connector tool descriptions were inspected without making a remote call. `create_tree` accepts an optional `base_tree_sha` and entries; `create_commit` accepts the target tree and explicit parent; `update_ref` accepts both `expected_sha` and `force`, and documents rejection of a mismatched expected head.

### Delta trees and sequential batches

`publish_snapshot.json` describes the changed paths, not a complete repository tree. Creating its 91/92 entries from scratch would omit preserved source files, earlier workflows, and both dependency gitlinks. The first tree request must therefore use the parent's tree, `39ae9a9edad9e0003f2df715c0b5ec4935c655f2`, as its base.

Each subsequent batch must use the tree returned by the immediately preceding successful batch. Reusing the original base for every batch would drop the changes submitted in earlier batches. The final returned tree SHA must equal the final local staged tree SHA exactly. That equality covers preserved files, paths, nested directory structure, modes, gitlinks, and content; a count-only comparison does not.

No current deletion entries or special-mode entries are missing: this snapshot has neither deletions nor mode changes. If the scope changes before the final freeze, regenerate the manifest from the final index/base diff rather than assuming that remains true. An intentional deletion would require an explicit deletion representation supported by the API; simply leaving its path out of a delta does not delete it.

For a new local blob absent remotely, send its exact string in the API's `content` field. The local snapshot SHA is an expected identity, not evidence that GitHub already possesses the object. Do not send both `sha` and `content` for one entry, or send local transport metadata such as `bytes` and `characters` as tree semantics. Preserve `path`, `mode`, and `type` explicitly.

### Chunked content

`read_publish_chunk.py` reads the immutable Git blob named by the snapshot, decodes UTF-8, slices the Python string, and prints the slice as JSON. This is preferable to reading mutable worktree files during transport, but its offsets/lengths are Unicode characters, not UTF-8 bytes or JSON-escaped lengths.

Parse each returned JSON string once and append its value in order. Preserve exact newlines, backslashes, indentation, Unicode, and the original final newline. Do not append the wrapper's printing newline, reformat Markdown/code, normalize line endings, or copy a truncated display. Assemble the complete file before creating its tree entry: separate tree entries for successive fragments of the same path replace content; they do not append fragments.

The closing blobs contain only BMP characters, so Python character offsets and JavaScript UTF-16 lengths agree for this observed snapshot. That convenience should not become a general assumption if future report text introduces non-BMP characters. Retain the recorded character length and byte/Git-SHA checks, and use the helper's character offset contract explicitly. Account for JSON escaping expansion when selecting request sizes.

### Commit object identity and publication race

Tree equality must be established before creating the candidate commit. Create exactly the intended single-parent commit, with parent `620b72e1fd9f0d63637c9a96d536113fc6f87d75`, and verify the response's tree and parent list. Creating an unreachable tree/commit is distinct from updating `main`.

Import or reconstruct the exact API-created commit object locally and verify its object ID before acceptance. Matching only tree and parent is insufficient: author, committer, timestamps/timezones, message bytes, extra headers, and final newline affect the commit SHA. An ordinary local `git commit` with the same message is not an adequate substitute. If reconstructing from API metadata, verify the resulting raw-object hash equals the API commit SHA before using it; otherwise retrieve the exact object through a supported route.

Run full acceptance on the resulting clean checkout with `--expected-commit` set to the API commit SHA. The receipt's source revision and source tree must match that object, with clean start/end source and pinned clean dependencies. Do not update the remote ref before this acceptance succeeds.

Immediately before branch publication, re-observe remote `main`. Use non-force `update_ref` with `expected_sha` equal to the reviewed parent and `sha` equal to the exact accepted commit. A lease rejection or changed parent requires inspection and integration, followed by the appropriate new candidate/tree/acceptance sequence. Do not silently substitute the new head in a retry, force-update, or overwrite upstream changes.
