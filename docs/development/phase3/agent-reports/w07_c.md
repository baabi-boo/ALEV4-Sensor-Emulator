## Findings and supported limits

### 1. Package loading remains a dependency setup side effect

`isetSpatialFixture` captures caller RNG before `requireIset`, then captures/restores `vcSESSION` and the full `ISET` preference group around fixture work. If `fspecial` is absent under Octave, `requireIset` loads the image package. It does not restore the original package/path state.

A single late-failure probe began with image unloaded, invoked the actual uniform fixture at exposure `1e6`, and reached the expected `ALEV4:ISETClippedFixture`. It confirmed unchanged RNG, global-name inventory and ISET preferences. `fspecial` changed from absent to present, and the path differed. The probe restored its own path before ending.

The adapter header promises RNG/session/preferences restoration, and the observed behavior satisfies that boundary. Root explicitly confirmed that image-package loading is expected dependency setup, so this is **not a production blocker or a request to expand scope**.

One documentation precision issue was sent to root: `docs/ARCHITECTURE.md` described the tests as preserving caller "session, preferences, path and RNG state." The missing-dependency subtest does restore its own temporary `rmpath`, but the suite's first image-package load persists. **Resolved by root and verified before this report closed:** the architecture now separately states that the adapter restores session/preferences/RNG, missing-dependency tests restore their temporary path removals, and an image package loaded by the adapter remains loaded. No documentation edit was made by this reviewer.

### 2. Binary layout is explicit; alternate host execution remains unmeasured

`spatialBundleUtil` opens binary payloads with `ieee-le`; writing iterates planes and writes each transposed plane, giving the declared plane-major/row-major layout. Reading uses the inverse reshape/permute. Shape descriptors explicitly retain rank and singleton spectral dimensions rather than relying on `ndims` to retain trailing singleton axes. Bounds limit shape products to 100 million samples and verify exact byte length before payload conversion.

Existing artifact tests contain independent little-endian IEEE-754/uint16 byte oracles and singleton/multibin cases. Those tests were inspected, not rerun here. The current local host is little-endian; a big-endian host, Windows filesystem, and native MATLAB byte I/O were not executed by this assignment. The explicit file machine format provides the intended portability mechanism, not measured evidence for every host.

### 3. Numeric JSON recovery preserves the tested binary64 values

The Phase 3 parser performs strict original-string/field checks and invokes the shared bounded grammar/duplicate scanner, then reconstructs numbers using their original lexemes through `str2double`. It retains scalar/vector/matrix wire kinds, rejects nonfinite and nonzero-underflow tokens, rejects NUL and malformed surrogate escapes, and bounds ASCII field names independently of an expanding host identifier limit. Reading the file also checks UTF-8 byte roundtrip.

The bounded probe compared `num2hex` before and after encoding and Phase 3 decoding for `7*6e-6`, `realmin`, `eps(0)`, `realmax`, and negative zero. All five hexadecimal representations matched exactly on Octave 9.4.0. This is a targeted representation check, not exhaustive proof that every `str2double` implementation rounds every possible decimal lexeme identically.

The frozen key exclusion list contains the MATLAB keyword list published by MathWorks; current official documentation does not support treating context-specific words such as `arguments` as additional `iskeyword` entries. No concrete keyword portability bug was established. The existing shared decoder still invokes the executing runtime's `isvarname`; future runtime changes require their own compatibility evidence rather than a permanent all-version claim.

### 4. File identity and hashing capabilities fail explicitly

The spatial helpers prefer native `lstat`, checking regular entry kind and device/inode identity. Their fallback uses Java NIO symbolic-link and same-file checks. The unsupported branch raises `ALEV4:SpatialFileIdentityUnsupported`; hashing raises `ALEV4:SpatialHashUnsupported` when neither native hash nor a JVM is available. The Phase 3 filesystem test helpers raise a capability error if they cannot create required hardlinks/symlinks. No successful skip is substituted for those checks.

The exporter validates parent identity before staging, refuses existing targets including dangling links, rejects staging collisions and ambiguous `mkdir` success messages, and installs recursive cleanup only after claiming fresh staging. Read helpers explicitly check successful-path close status; quiet `onCleanup` remains for already-failing or already-closed handles. Existing ownership/close-error regressions were inspected, not rerun.

A bounded Java primitive probe exercised the exact MessageDigest byte-conversion expression and Java NIO methods used by the fallback, on the local Octave/JVM combination. Hashing `[0 1 127 128 255]` through Java matched the native helper; Java detected a test-owned hardlink and symlink. **The production fallback dispatch itself was not forced:** native `lstat` and `hash` remained available. This establishes local Java primitive compatibility only. MATLAB's Java bridge, `-nojvm`, absence of native/JVM capability, nonlocal filesystem behavior, and concurrent publication remain unexecuted or outside the documented contract.
