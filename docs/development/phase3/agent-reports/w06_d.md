## Finding 1: caller Git overrides could hide dirty source

The original `git()` helper inherited the caller environment. A focused
read-only probe extracted the existing committed tree with `git archive HEAD`
into an owned temporary directory and set `GIT_WORK_TREE` to that clean copy.
Using the actual helper and actual Git:

```json
{
  "actual_dirty": true,
  "actual_status_entries": 46,
  "redirected_dirty": false,
  "redirected_status_entries": 0,
  "source_head": "620b72e1fd9f0d63637c9a96d536113fc6f87d75",
  "override": "GIT_WORK_TREE"
}
```

Thus the same observed HEAD could accompany a cleanliness check of another
tree. This probe established a false cleanliness predicate; it did not claim
that a complete numerical release run was executed under that override.

The fix removes every inherited `GIT_*` variable for both direct Git reads and
all child gate processes. This includes worktree/index/common-directory
overrides and configuration injection through `GIT_CONFIG_COUNT`,
`GIT_CONFIG_KEY_*`, `GIT_CONFIG_VALUE_*`, and `GIT_CONFIG_PARAMETERS`. Other
environment variables remain intact. The source directory must also equal
Git's actual reported top-level worktree before any output directory or gate
is created.

The new real-Git test establishes two actual dirty-tree masking controls
(worktree-only and combined Git-directory/worktree/index/common-directory
overrides), then verifies that the production helper still observes the dirty
source and rejects release execution before output creation. It separately
establishes real configuration injection through both configuration-variable
mechanisms and verifies that the helper removes it. The mocked orchestration
control checks environment isolation on all 16 external subprocess calls and
checks preservation of a non-Git sentinel environment variable.

## Finding 2: the preserved Phase 1 verifier accepted hardlinked repeats

`verify_phase1_artifacts.py` checked distinct resolved demo directories and
byte equality but did not check file identities. Its existing artificial
format fixture was copied with `shutil.copytree(..., copy_function=os.link)`.
The unchanged verifier returned:

```json
{
  "status": "passed",
  "compared_demo_byte_identical": true,
  "artifact_count": 31,
  "aliased_file_count": 31,
  "fixture_only": true
}
```

This is an independent-verifier gap. It is not evidence that the real
orchestrator's freshly generated demo trees were aliased.

At the root agent's direction, the fix is at the **Phase 3 orchestration
boundary**, preserving all earlier-phase production files. Before each phase's
existing verifier call, the orchestrator now:

1. Requires actual, nonsymlink output/phase/demo/repeat directories.
2. Walks both artifact trees using `lstat`; directories are traversed explicitly
   and symlinks or other nonregular entries are refused without opening them.
3. Rejects missing or empty demo trees and aliased demo roots.
4. Requires disjoint `(st_dev, st_ino)` file-identity sets across the primary and
   repeat trees. This catches both same-filename and cross-filename hardlinks.
5. Records phase, paths, checked file counts, status, and `nonaliased` in the
   aggregate receipt's `repeat_identity_checks` list. A failure records an error
   and stops before that phase's artifact verifier can report a pass.

Valid separate files with identical bytes pass. Regression controls cover
same-filename and cross-filename hardlinks in **each of Phases 1, 2, and 3**;
symlinked primary/repeat/phase roots, a symlinked payload and nested directory;
and zero-exit demo commands that leave missing or empty evidence trees.

The standalone historical Phase 1 verifier remains unchanged and retains its
older hardlink limitation. The complete Phase 3 acceptance command now enforces
the documented nonalias requirement for all three phases independently of
that earlier verifier.

## CI wiring review

The Phase 3 workflow targets `ubuntu-24.04`, sets a 35-minute job timeout,
checks out recursive submodules, disables persisted checkout credentials,
and uses full SHA pins for checkout and artifact upload actions. It installs
`octave`, `octave-image`, and `octave-statistics`; the ISET adapters explicitly
load the image package and fail when it or `fspecial` is absent. The full
acceptance command receives `--expected-commit "$GITHUB_SHA"` and uses the
default fresh `outputs/phase3-acceptance` tree.

The artifact-upload step uses `if: always()`, requires files, uploads the
entire acceptance tree including repeats/logs, and retains it for 14 days.
Normal gate failures therefore reach the retention step. Job cancellation or
infrastructure failure is not proof of a completed upload. Actual runtime
adequacy of the 35-minute budget requires observed CI execution.

The earlier Phase 1/2 workflows remain present with their original numerical,
failure, demo, repeat, independent-verifier and dependency checks. Phase 3
also executes their preserved gates inside its complete acceptance command.
The operating-system packages are repository-selected rather than pinned to
exact package versions; the numerical reports record the runtime that actually
executes. This audit does not invent an exact future CI runtime or CI pass.
