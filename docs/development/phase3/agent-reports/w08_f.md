## Concrete findings and observed fixes

### 1. Aggregate exclusion previously skipped every basename `acceptance.json` — fixed

The initial helper used `path.name != 'acceptance.json'`. That would omit an unexpected nested file with that basename, breaking the promised exact file-set comparison and potentially missing an unmanifested file. The current helper instead uses:

```python
path != source / 'acceptance.json'
```

This now matches the production runner's root-only aggregate exclusion. All other regular files participate in the length/SHA-256 inventory. `lstat()` rejects symlink and other nonregular entries before the equality check.

### 2. Command associations previously checked labels alone — fixed

The revised helper compares ordered `(label, stdout, stderr)` triples against the plan. This binds the retained output paths to the actual 16 recorded command entries, in addition to requiring all 16 exit codes to be zero. A changed stdout destination can no longer evade the retention association check merely by preserving its command label.

### 3. Copied bytes previously lacked a copy-time link to the validated inventory — fixed

The initial scan proved that source files matched the aggregate, but the copy loop subsequently reread sources without comparing that later content to the validated inventory. The revised helper now captures the original aggregate's raw bytes before parsing, requires those exact bytes for its retained aggregate copy, and rechecks them at the end. Every other retained file's copy-time length/SHA-256 must equal its aggregate manifest entry. Source and destination bytes are also compared directly.

This prevents the derived catalog from silently describing different receipt or retained-file bytes than were validated. The caller must still wait for actual process completion; the helper does not observe the runner's operating-system exit status.
