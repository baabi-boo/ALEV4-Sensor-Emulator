## Minimal API recommendation

1. `geometry = alev4.createSensorGeometry(overrides)` validates a separate schema with `schema_version`, `full_grid_size`, `active_roi`, `pixel_pitch_m`, `origin_xy_m`, `full_grid_cfa_pattern`, and `parameter_sources`. Follow existing constructors: reject unknown fields; normalize accepted real finite numeric values to dense double arrays; reject complex, logical numeric substitutes, malformed structs and unsupported ranges.
2. `grid = alev4.sensorGrid(geometry)` returns active x/y edge vectors and center vectors, active image size, active CFA pattern, physical full/active extents, and the normalized geometry. Avoid allocating full H-by-W coordinate meshes or full CFA maps just to determine an active crop. A full pixel grid need not be allocated to describe it.
3. `bound = alev4.bindSensorGeometry(readout, geometry, mode)` with documented `mode='derive'` versus `'validate'`. Derive copies the caller's validated readout and replaces only the single sensor's or dual configuration's nested sensor `image_size`, `pixel_pitch_m`, and `cfa_pattern`. Validate requires these three fields already to match and raises a specific conflict error. Dispatch single/dual through explicit validated schema or explicit readout mode; never guess merely from one arbitrary field.

An equally acceptable simpler arrangement is a derive-only helper plus separate binding validator inside the spatial exposure wrapper. Avoid an implicit default whose meaning changes depending on whether the caller happened to provide a fully populated config.

## Coordinate and CFA contract

- All dimensions use `[rows columns]`; origins use `[x y]`; ROI is one-based `[first_row first_column height width]`.
- Full-grid edge coordinates start at `(x0,y0)`, with x increasing with columns and y increasing with rows. The width is columns times pitch; height is rows times pitch.
- Full-grid column c center is `x0+(c-0.5)*p`; row r center is `y0+(r-0.5)*p`. Active edges start at `x0+(first_column-1)*p` and `y0+(first_row-1)*p`.
- CFA pattern is anchored at full-grid (1,1). Derive active tile using both offsets modulo 2, not by unconditionally retaining `RGGB` or restarting color at the ROI.
- For full `RGGB`, crop start parity `(odd,odd)`, `(odd,even)`, `(even,odd)`, `(even,even)` yields `RGGB`, `GRBG`, `GBRG`, `BGGR`, respectively. Equivalent transformations must work for each starting pattern.
- Cropping occurs in physical/grid coordinates. An active output does not inherit full-grid noise realizations unless explicitly designed to do so: full-frame random draws versus a smaller standalone crop use different shape/order. Test deterministic crop expectations and CFA; require exact noisy identity only for the identity full-grid crop with unchanged shape and seed.

## Validation that matters

- Grid sizes and ROI components must be positive finite exact integers; avoid overflow in `start+length-1` by checking `length <= full_size-start+1` after checking start bounds.
- Retain the existing 100-million-pixel bound, including a division-based product guard, unless a separately documented descriptor-only limit is intended. Check both full grid and active grid before allocating.
- Square pitch must be positive finite and have positive finite representable `p^2`, matching current collection-area support. Do not accept a two-element pitch while integrateExposure still uses p squared.
- Require finite origin, derived full/active edges, centers, and extents. Finiteness alone is insufficient: a very large coordinate offset combined with a tiny pitch can collapse adjacent edges or centers to identical doubles. Reject that range rather than emitting a zero-area or ambiguous grid. Validate representable spacing where edge vectors are built, and avoid tolerance floors of 1 metre that dwarf micrometre geometry.
- Independently published sensor width/height belong in the source register as observations, not as independent freely adjustable geometry fields. Preserve supplied precision and explain any discrepancy with grid-times-pitch.
- Generic defaults can remain 32-by-32, 6 micrometre square pixels, full ROI, origin zero, RGGB, but provenance must call these assumed/generic. A manufacturer profile requires primary evidence; Bayer spectral curves and fill factor remain assumed without measurements.
- Source references should use stable record IDs with validated types, not unchecked arbitrary structs that later cannot serialize. Exact metadata conventions should be frozen before artifact writers.

## Independent acceptance test matrix

1. Hand-computed 3-by-5 grid at p=2 and origin [10,20]: full centers x=[11,13,15,17,19], y=[21,23,25], edges x=10:2:20, y=20:2:26. Crop [2,2,2,3] has x=[13,15,17], y=[23,25], active extent [6,4], and BGGR from RGGB. Use a separate loop/scalar oracle.
2. All 4 full Bayer patterns times all 4 ROI offset parity combinations, with odd dimensions and singleton row/column outputs. Compare independently cropped full CFA arrays with active CFA arrays.
3. Full-grid identity for single and dual readouts: same expected electrons, incident photons, actual noise/RAW and seed as existing APIs. Use at least one noisy seeded case; retain caller RNG and original configuration.
4. Deterministic nonidentity ROI on nonuniform multi-bin input: compare cropped full expected electrons against directly evaluated active config. Do not falsely assert bit-identical independent cropped noise draws.
5. Binding tests independently change size, pitch and CFA; validate mode rejects each conflict; derive mode preserves QE, spectral bins, fill factor, full well, shot-noise choice, all electronics and merge thresholds. Confirm dual canonical shared electronics remain unchanged.
6. Invalid inputs: empty/wrong-rank dimensions, NaN/Inf/complex, fractional or zero ROI, ROI at boundary versus one step beyond it, huge dimensions/product, p=0/underflow/overflow, nonfinite derived coordinate, huge-origin/tiny-pitch collapse, wrong strings, unknown fields, unsupported schema, and malformed provenance IDs.
7. Every geometry/sampling helper consumes no RNG, including rejection paths. Demonstrate caller structs remain equal before/after helpers.
8. Future spatial wrapper must call spectral integration on averaged irradiance, not area-integrated counts, and must not apply fill factor by shrinking the footprint as well as by scaling charge.
