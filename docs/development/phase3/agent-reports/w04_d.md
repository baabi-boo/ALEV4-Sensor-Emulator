## Implemented coverage

The 68 Python-standard-library unittest methods comprise 43 bundle tests,
11 numerical-report tests, and 14 full-release/receipt tests. All artifacts
are created in temporary directories from independent handwritten or analytic
fixtures. No Octave, MATLAB, ISETCam invocation, native generated output,

The small spatial fixtures have explicit independent answers:

- Nonuniform two-bin overlap on an offset BGGR crop yields sampled planes
  `[30,35]` and `[60,70]`, then `[56.25,48.125]` electrons. Single RAW is
  `[100,97]` after physical clipping and half-step ADC rounding; exact
  little-endian bytes are asserted. Dual high/low codes are `[255,255]` and
  `[102,98]`, with merged `[50.25,48.25]` and flags `[69,196]`.
- An even asymmetric 2x3 PSF with explicit origin `[1,2]` and two independently
  associated kernels yields optical planes `[13.125,26.25,210,420]` and
  `[0,0,0,4]`, then crop-CFA electrons `[4.921875,6.5625,52.5,54]`.
  The shared-kernel variant has separately handwritten outputs. Both single
  and dual pre-PSF paths are exercised.
- One-bin/one-pixel pre/post identity cases retain explicit cube shape.
  Both `1e-280` and the minimum positive binary64 subnormal survive exactly;
  refreshed-hash zero substitutions reject.
- A deterministic dual identity case distinguishes observable smoothstep
  reconstruction, physical saturation, exact upper-rail invalidity, and actual
  ADC clipping. Replacing the observed merge with hidden expected charge fails.

Corruption cases refresh SHA-256 deliberately when testing physical checks,
so hash rejection cannot mask incorrect overlap, convolution, spectrum/QE,
readout, or flag validation. Tests cover malformed/duplicate/escaped-key JSON,
invalid UTF-8, numeric overflow/underflow, booleans in numeric fields, explicit
rank/product/byte limits, foreign and missing fields, source-list syntax,
mode/stage/order, crop parity, geometry resolution, PSF spectral order and
origin, nonuniform PSF sampling, a one-ULP coverage gap, and a removed PSF halo
whose remaining optical array is still the correct valid convolution.

File tests cover all binary types, truncation/trailing bytes, descriptors,
endian interpretation, symlink manifest/payload/directory, FIFO rejection
without blocking, same-bundle hardlinks, cross-bundle aliases, same-directory
repeat, hardlinked repeat, and cross-filename repeat aliases with equal legal
bytes. A second semantically identical JSON encoding fails byte-repeat
verification as required.

A complete artificial 66-file/eight-frame demo and complete artificial nested
Phase 3/2/1 report exercise `verify_outputs` and CLI behavior without mocks.
Its seven analytic fixtures and ISET-shaped affine fixture are fabricated
parser data, explicitly labelled as such; neither the fixture nor report
claims genuine numerical execution. Tests require every numerical suite,
literal pass/prerequisite/execution flags, fixed dependency pins, source and
runtime association, matrix-derived ISET error, refinement controls, summary
recomputation, exact artifact/report hashes, and honest false scope flags when
repeat or random-stream/source authentication was not performed.

## Production issue found and fixed by the owner

`check_iset_report` accepted `True` in place of the first numeric element of
either `native_samples_per_axis` or `source_refinement_factors`, because direct
Python list equality treats `True == 1`. This was reproduced and reported to
root. Root changed the production verifier to validate each refinement count
through `integer` before sequence comparison. The focused rejecting regression
now passes for both fields. This agent did not edit that implementation.
